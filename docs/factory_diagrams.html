1Factory overview

Scout heads roam the archives and write prospects. Triage scores them; promote turns approved prospects into work orders on the line — carrying scout provenance with them, never re-typed. The line runs the two nested loops and emits the three-file Ariadne bundle. Opportunity-mode prospects ride the same factory on a cheaper recipe.

2The page line (small loop)

One page in, one assembled bilingual page record out. Stations (rounded) never call each other — data flows only through workspace artifacts (rectangles), each provenance-stamped. The recipe binds each station's swappable parts: model, prompt, params, cleaning profile. Pages move through the line in parallel.

There is deliberately one read slot, not OCR + transcribe: the factory is VLM-native. A corpus needing two reading passes puts two read stations with different prompts in its recipe.

3The manuscript line (big loop)

Item-level stations. survey runs once all reads land and builds the jig the page line's translate needs — so the conductor interleaves the loops: reads stream in, survey fires, translations resume. reconstruct repairs page-boundary breaks and collates continuous original + English; emit packages the Ariadne handoff.

4The ledger: inventory ⋈ production log

One SQLite database, library/factory.db. The join answers both directions: “what has the Gallica head found that we haven't run?” and “which pages of Pal.lat.1267 were read by read/v1 on the old model, at what cost?” stage_runs is append-only — refreshes add rows, never overwrite. Current state is the stage_state view (latest successful run per doc/page/station).

5Freshness state machine

Every completed stage is judged by its two fingerprints. Config drift (recipe now binds a different model/prompt/params) marks it outdated — never redone automatically, because redoing paid API work is an explicit decision. Input drift (upstream was refreshed) marks it stale — plain run rebuilds it to restore line consistency. 

stateDiagram-v2
  [*] --> Missing : station owes this artifact
  Missing --> Running : conductor schedules
  Running --> Failed : error (logged, append-only)
  Failed --> Running : next run retries
  Running --> Fresh : complete_run

  Fresh --> Outdated : recipe config changes
(config_fingerprint drift)
  Fresh --> Stale : upstream refreshed
(input_fingerprint drift)
  Outdated --> Running : explicit run --refresh station
  Stale --> Running : plain run rebuilds
  Outdated --> Fresh : recipe reverted

  note right of Outdated
    Paid work is never silently redone.
    Outdated waits for an operator decision.
  end note
  note right of Stale
    Stale no longer derives from what is
    above it, so run restores consistency.
    Byte-identical refresh output does not
    propagate staleness downstream.
  end note

6Refresh cascade: a better model ships

The operator points the recipe's read slot at the new model and refreshes one stage. Downstream stages go stale page-by-page as new reads land; the next run rebuilds exactly what stopped deriving from its upstream — and nothing else. Both generations of every page remain in stage_runs forever. 

sequenceDiagram
  actor Op as Operator
  participant C as Conductor
  participant L as Ledger
  participant R as read station
  participant T as translate station
  participant A as assemble_page station

  Op->>Op: edit recipe — read slot → new model
  Op->>C: palimpsest status --doc-id X
  C->>L: compare fingerprints vs recipe
  L-->>Op: read OUTDATED (config drift) · rest fresh

  Op->>C: palimpsest run --doc-id X --refresh read
  loop each page, parallel workers
    C->>L: begin_run(read, page, new config_fingerprint)
    C->>R: read page with new model
    R-->>C: page_transcription v2
    C->>L: complete_run(output_fingerprint v2)
    Note over L: translate + assemble for this page
now STALE (input fingerprint mismatch)
  end

  Op->>C: palimpsest run --doc-id X
  loop each stale page
    C->>T: retranslate (same config, new input)
    T-->>C: page_translation v2
    C->>A: reassemble page
    A-->>C: page_assembled v2
    C->>L: append runs (v1 history preserved)
  end
  Note over C,L: manuscript line (reconstruct, emit)
rebuilds last, once pages settle
  C-->>Op: line consistent — all fresh
