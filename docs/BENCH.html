The Bench

How a module leaves the production line, gets experimented on, proves itself against a number, and is bolted back in — or deleted. The lab is not a place; it is a loop with a gate.

The premise

The factory's production line is deliberately rigid: stations communicate only through fingerprinted artifacts, every artifact declares its contract, and the conductor re-runs exactly what a change makes stale. That rigidity is what makes experimentation safe — a module boundary is a socket, and anything that honors the contract can sit in it. Swapping the emendation executor from one agent harness to another changed zero lines of architecture; that was the proof.

The bench turns that property into a workflow. Three pieces: the socket, the fixtures, and the promotion gate.

1 · The socket

A module's interface is one callable and one artifact contract — nothing more. align is anything that maps (image, lines) → page_alignment. An emendation executor is anything that satisfies the AgentRun contract. A future glyph generator is anything that maps exemplars → glyph images, tier-stamped. There is no plugin framework, no strategy registry, no abstract base hierarchy: the artifact contract is the abstraction, and it already exists because stations only talk through artifacts.

house rule. One implementation in the tree at a time. An interface with one implementation is scaffolding, not architecture — the socket earns a second implementation only for the duration of an experiment, and the experiment ends with one implementation again.

2 · The fixtures and the scoreboard

Every module owns a frozen fixture set — real inputs snapshotted from the library — and a deterministic metric. Experiments run incumbent and candidates against the same fixtures and render one table. For model-backed modules the scoreboard adds the blind pairwise judge; for pure code it is numbers alone, and costs nothing.

# the shape of every experiment
factory bench align \
    --candidate experiments/hough_columns/candidate.py
# → scoreboard: incumbent vs candidate, per fixture, one metric

Candidates are loaded by path. They live in experiments/, outside the package; the production tree is never touched until promotion. Three rival ideas are three directories, all runnable in one command, none of them contaminating the line.

boundary. The bench measures modules against fixtures; evaluate measures whole-line output against references. Keep them separate — a module-level win that does not survive line-level evaluation is how an over-fitted part sneaks onto a production line.

3 · The promotion gate

A candidate that beats the incumbent is promoted in place: its code replaces the incumbent's, the suite and golden fixtures run, and one commit carries the scoreboard in its message. Then the experiment directory is deleted. Losers are deleted too, immediately.

Git is the only version store. There are no _v2 files, no commented-out alternatives, no "old approach kept just in case" — a worse implementation held in the tree contaminates every future reading of the code. What survives a losing experiment is one line in experiments/LOG.md:

2026-07-20  align/columns   Hough-transform column detection
            lost to projection profile: 61% vs 86% boxed. Deleted.

That line is the lab notebook. "We tried that in July and it lost by 25 points" is knowledge worth one sentence — and no more than one sentence.

The loop, proven before it was named

The bench codifies a practice, not a plan. Each of these ran the full loop by hand before the harness existed:

experimentgateverdict
read decoding: temp 0.7/no-thinking vs 0.1/thinking (zh) deterministic metrics + blind judge promoted — per-lane decoding, seam variance gone
emend executor ladder: five models, two harnesses 12-point reference scorecard promoted — frontier dossier + light emender
reference dossier vs solo emender same scorecard, A/B promoted — dossier doubled the light model's score
ink-primacy rule re-run on the contaminated fixture promoted — one surgical ink-cited emendation
align glyph scale: blob heights vs column-pitch autocorrelation boxed % + visual audit promoted — and the "100% boxed" mirage retired

The mirage in the last row is the reason the bench insists on audited metrics: the first align prototype scored perfectly by matching stroke fragments. A metric is only a gate after it has been checked against the ink once. Fixtures make that check permanent.

Changing a tire, end to end

The glyph-generation module, walked through the whole cycle:

unplug

Socket: generate(char, exemplars) → glyph. Fixture: the exemplar library; hold out attested characters.

experiment

Candidates: few-shot image-model call vs a fine-tuned font-generation model — each a directory under experiments/.

measure

Scoreboard: generate the held-out characters, score against the scribe's real ink. One number per candidate, per manuscript.

send it back

Promote the winner into the recipe slot; scoreboard in the commit; delete the rest. The line never noticed.
